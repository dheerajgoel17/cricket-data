# The iOS / Android app (`mobile/`)

Expo (React Native, TypeScript), one codebase, two store builds. Free, no accounts: saved state stays on the device (MMKV through `@cricket/storage`). Agent rules: `mobile/AGENTS.md`.

## What is shared with the site, what is not
* **Shared, imported from `site/` (see `mobile/metro.config.js`, `tsconfig.json`):** `@cricket/engine` (all numbers and rules), `@cricket/storage`, `@cricket/tokens` (colours come from `tokens.json` as they are), and pure files from `site/src/lib`: `priority.ts` (rail ranking), `home-phase.ts` (In play / Pre-match / Resulted), `assets.ts` (flag URLs), `hot-lines.ts` (which lines Hot props scores, their order), `books.ts` (book logos) and `format.ts` (odds, short venue names).
* **Not shared:** components, pages, hooks. The UI is React Native (`mobile/src/ui`, `mobile/src/app`); sizes keep the web's role names with native values (`src/ui/tokens.ts`).
* **Copied, to be moved into the engine:** these mirror React code that cannot be imported, so a change to the original needs the same change here until Phase 1 moves the logic into `site/packages/engine` and both import it: `src/lib/rail.ts` (`usePricedFixtures` in `site/src/hooks/useEngine.ts`, `useHomeRail`, and the phase counts of `site/src/pages/Home.tsx`) `src/lib/card.ts` (`FixtureCard` in `site/src/components/app/fixture-card.tsx` and `playState` in `site/src/lib/play-state.ts`: live / started / delayed / final, scores, status line; a started match has no LIVE badge and says the source has no score), `src/lib/hot.ts` (`useHotRows` in `site/src/components/app/hot-props.tsx`: the scoring loop around the engine; `useTick` / `StandingMark` in `src/ui/tick.tsx`) `src/lib/fancy.ts` (`useFancyCards` in `site/src/hooks/useFancyCards.ts`) and `src/lib/player.ts` (`PlayerScreen`, `nextMatch` and the chart numbers in `site/src/pages/player.tsx`; `deriveChart` is pure and tested).

## Data path
The app reads the same files as the site: `/data/*.json` and `/api/live`, through the data gate.
* `GET /api/gate` returns the cookie and the unwrap key (`X-Cd-K`). The app sends the cookie header by hand (no browser cookie jar) and refreshes it on a 403 (`mobile/src/lib/net.ts`).
* Every request carries its own user agent (`FancyCash/<version> (<os>)`). Android's default one (`okhttp`) is on the gate's block list and is refused everywhere. The gate today lets in any client that is not on that list and sends no `Sec-Fetch-Site`; that is a speed bump, not a lock, so a key kept in the app would not be one either. If the gate is tightened, give the app its own explicit way in rather than a browser-looking user agent.
* The small files (fixtures, photos, identity) and `/api/live` arrive wrapped (`engine/wrap.js`: SHA-256 keystream). The unwrap needs `TextDecoder` and `crypto.subtle.digest`, which Hermes lacks; `src/lib/polyfills.ts` supplies both (SHA-256 from `@noble/hashes`, MIT, synchronous, because the unwrap hashes one small block per 32 bytes and a native call each would be thousands per poll). It is installed first, from `mobile/index.js`. The digest hands the main thread back after 8 ms of work (`FRAME_MS`), so a big file does not hold the screen.
* The site URL is `EXPO_PUBLIC_SITE_URL` in `mobile/.env.local` (ignored). It ends up in the built app, never in a tracked file.
* The stats engine's data (`src/lib/data.ts`): `meta.json`, `index.json` and `matches.json` (about 4.5 MB) load once, then a player's own file (`p/NN.json`, 0.5 MB) when a row needs it. Hot props scores one day's priced lines against those files (`src/lib/hot.ts`, `use-hot.ts`).
* Team crests are the source's logos from `photos.json` (`teamLogos`), else the national flag (`flagUrl`), else initials, as on the site.

## Look
The Home tab follows the site's phone Home: the brand header, series chips, 80%-width snapping fixture cards (state and format, crests, scores or start time, status line, series, Props), the floating In play / Pre-match / Resulted bar, and the five tabs (Fixtures, Player props, Fancy, Leagues, Saved). Colours come from the shared tokens; type is the site's: Inter for text and, in Semibold with figures of equal width, for numbers and the small caps labels (`font`, `cap`, `num` in `src/ui/tokens.ts`), loaded in `app/_layout.tsx` with the splash held until they are in. Below the rail: the market tape ("High odds hits" / "Low odds misses") and "Hot props", a four-row teaser of the day's best player props (face in team shirt, name and flag, line, edge, book logo and price, so-far and Cleared / Missed from the live feed, L10 and ground rates, last-games bars). The Player props tab lists the day's rows with the same row, a day chip row (Today, Tomorrow, then dates) and pull to refresh. Motion: pulsing LIVE dot, cards and rows rise and fade in one after another, pulsing placeholders and a spinner while lines are scored, price and so-far flashes with an arrow when they move. Native components wherever there is one: the system tab bar, `Segmented` (SwiftUI picker on iOS, Compose segmented buttons on Android: Over / Under, format, innings, In play / Pre-match / Resulted, Lines / Game log / Splits), and system form sheets for the info popovers (`app/info/[topic].tsx`, topics in `lib/info.ts`). Page headers and the filter bars are `BlurBar`s over the scroll view (a `BlurTargetView`); the sub-bars (format, innings) collapse as you scroll down (`useCollapseOnScroll`). Filters, alt lines and splits are accordions (`ui/accordion.tsx`, height and chevron animated on the UI thread). Loaders (`Working`) are centred in their section or page. The tab icons are the site's Ionicons, drawn as images (`assets/tab-icons`, made from the `ionicons` package). To compare with the site, run the browser preview (below) next to the live page at 375 px: the counts and the first chips are the same.

## Pages
The root is a stack with the tab group on the bottom (`src/app/_layout.tsx`, `(tabs)/_layout.tsx`); a page one level down is pushed over the tabs and has the reference app's header (`ui/page-header.tsx`: a round back button, the name and what it is centred, round Save / Share buttons at the right) and the system swipe-back. Taps (`src/lib/nav.ts`): a fixture card opens `/fixture/<id>`; a prop row or a market-tape row opens `/player/<index>?stat=&line=&fmt=&scope=` (the site's own parameters, plus `team`); "See all" opens the Player props tab.
* **Fixture page** (`app/fixture/[id].tsx`): the match in a container (`ui/match-header.tsx`: state and format, both sides with crests and scores, or the kick-off and a live countdown, status, series and ground) and the site's four sections as a native segmented control in the blurred bar: **Props** (the player props priced for that match, scored like Home's, with a stat switch when there is more than one), **Fancy** (`ui/match-fancy.tsx`: scope Match / each side, L5 to L30, the teams' form or the ground's matches, "Bookmaker lines" ranked by edge, and for the chosen market the median, a chart of the matches against the line, the over / under shares with fair prices and the books' prices, the ground note and a tappable line ladder; Top batter is a list), **Grid** (`ui/grid-table.tsx`: players down, the side's last fixtures across, tinted by distance from the line, names fixed while the fixtures scroll) and **Trends** (the players who clear a line most often). Props and Fancy only show when the books price them. A first-class match says it has no player props. Share sends the match text and link. `?tab=fancy&fm=<market>&sc=<side>` opens a market from the Fancy tab.
* **The live match** (`ui/live-board.tsx`): while a match is on, the pair at the crease with their partnership, the last wicket, the bowler, this over's deliveries and the run rates; under the match two closed rows, **Scorecard** (innings picker, batting and bowling tables, fall of wickets, yet to bat; so far only, never used for settlement) and **Recent form** (each side's last results, `ui/recent-form.tsx`, `lib/form.ts`). A finished match whose lines the live feed has let go is read from its permanent archive file (`lib/archive.ts`, the address in `EXPO_PUBLIC_ARCHIVE_URL` in `.env.local`), so a link to an old match still shows its props.
* **Fancy tab** (`app/(tabs)/fancy.tsx`, `lib/fancy.ts`): every priced match not yet over with its best-edge markets (the book's line, the edge, the last ten results as bars, the other books behind "+N books"), in the Home rail's order; each card opens its match's Fancy section. Matches are scored one at a time with the main thread given back in between.
* **Leagues tab and competitions** (`app/(tabs)/leagues.tsx`, `app/competitions.tsx`, `app/league/[id].tsx`, `ui/tournament-stats.tsx`, `lib/league.ts`): the league chips (live and soon first, Big Bash on top), then the season picker, the season in four numbers, the leaders rail, Batting / Bowling / Overall lists (best five, "Show all") and the season-by-season bars. "More" opens the competition (Stats, Markets, Teams, Results); "All competitions" lists every one with eight matches or more.
* **Team page** (`app/team/[idx].tsx`): format, then Player grid (stat, line and games), Markets (the engine's match markets over the team's matches, a ladder for each) and Top batter (the team batting first); the star saves the team.
* **Saved tab** (`app/(tabs)/saved.tsx`): the watchlist (props), saved players and teams, and recently viewed players, all on the device. **Search** (`app/search.tsx`, the button in the header): players (typo tolerant), teams, matches and leagues; empty, it offers the tabs and the last players opened.
* **Player page** (`app/player/[idx].tsx`, logic in `lib/player.ts`), in the site's order: the stat switch and the format / innings segmented rows (the last two tuck away on scroll); the player's name, team and picture; hit rate gauge with hit rate, fair price, last-20 average and the line, and the prop / opponent strip; Over / Under, the line stepper (one capsule: minus, the line, plus) and the watchlist star; "Alt lines" (every line the books price, edge on each); the bar chart with the line, values in the bars, date and opponent under every bar (every other one past ten games) and the look-back windows with their hit rates beside a round filter button; the next match in a container (start time or LIVE or Completed, the line with whether it cleared and the best price, the books' table, two tiles with his rate at the ground and against that side; the reading notes are behind its info button) with "Chart filters"; the Filters accordion (opposition, venue, home / away, batted first / chasing, position, level, last games; they re-run the engine plan); at a glance (cleared, hit rate, fair price in one card) and the data date, and Lines (the ladder with the chart's line highlighted, and "when it hits") / Game log (a tap opens the game) / Splits tabs. Tables fit the screen width (`DataTable` weighs its columns, `Pill` keeps a column of tinted figures aligned); none scrolls sideways. The games come from the engine once per stat and format; moving the line only recomputes the rates.

## Glass
Dark only. iOS: the system tab bar (`expo-router/native-tabs`) and `GlassView` (`expo-glass-effect`), which are liquid glass on iOS 26 and later and a system blur before. Android has no system glass: the tab bar is ours, a `BlurView` (`expo-blur`) over the screens' `BlurTargetView`, and the target must not contain the blurring view. Surfaces inside the screens on Android are a solid tint. See `src/ui/glass.tsx`, `src/components/app-tabs*.tsx`.

## Run it
```bash
cd mobile && npm ci
printf 'EXPO_PUBLIC_SITE_URL=%s\n' "$SITE_URL" > .env.local     # the site's address, from site/.env.local
npm run typecheck && npm test
npm run web              # browser preview on :8082 (react-native-web); Metro proxies the site (dev-proxy.js), no gate or cookie needed in the browser
npx expo run:ios          # full Xcode, selected with xcode-select
npx expo run:android      # JDK 17 (JAVA_HOME) and the Android SDK (ANDROID_HOME) with an emulator or phone
```
The preview shows layout, type and data, not the native glass or the system tab bar (a plain bar stands in, `app-tabs.web.tsx`). Android is not being rendered for now; the code and the build are kept working.
`android/` and `ios/` are generated by `expo prebuild` and not committed.

## Checked so far (2026-11-01)
* **Browser preview against the live site** (375 px wide): header, chips, card layout, crests, the phase bar and the tab list look the same, and the bar counts and first chips equal the site's for the same data ("In play 7, Pre-match 6, Resulted 11"). An earlier version showed 31 under In play because it counted and listed games with no props there; the site counts priced games only and lists the others under Pre-match, now copied (`phaseView`, tested).
* **Android emulator** (Pixel 7 profile, API 34, arm64, debug build; the first Gradle build took about 16 minutes), on the first version of Home: data through the gate, live scores, the pills, the tabs, and a translucent blurred tab bar (subtle on a dark screen). Not re-run since the Home redesign.
* **Unwrap cost on the JS thread** (emulator, debug build): fixtures 268 ms, `/api/live` 407 ms. `/api/live` is fetched every 15 s, so a slow phone (several times slower) would hold the JS thread for over a second per poll. Not yet measured on a release build or a low-end phone. Options if it is a problem: unwrap in slices that yield to the UI, or move it into a native module.
* **iOS Simulator** (iPhone 17 Pro, iOS 26.5, Xcode 26.6, debug build; needs CocoaPods, installed with Homebrew; first build several minutes): the app launches, loads the live data through the gate (flags, logos, live scores, status lines), the system glass tab bar floats with a filled pill on the chosen tab, the phase bar sits above it with a gap, the pills and chips switch the lists, the card rail scrolls sideways and snaps with the next card peeking, and all five tabs navigate. The splash shows the site icon as a square tile.
* **Hot props on iOS** (same simulator): the market tape and four prop rows match the site's content for the same moment (G Redmayne 11.00, Bassingthwaite 4.00 and so on); Player props lists the day's rows. Timing, debug build on an Apple-silicon Mac: the stats data loads in 2 to 2.6 s; scoring 419 priced lines into 286 rows takes 6.5 to 7 s in the background (the screen stays usable; rows appear as they finish). A release build on a phone, and a low-end Android, are not measured; if it is too slow: score in-play matches first, keep scored rows on the device between launches, or score on the server.
* **Pages on iOS** (same simulator): tapping a match card opens its page; a prop row opens the player on the row's line (JF Smith, 19.5 runs: hit rate 44%, 4 of 9, fair odds 2.25, the chart and the log); the back button returns; Oman v Netherlands lists its four players' props; a first-class match and a match with only team markets say so. Not compared line by line with the site's pages.
* **Reference redesign and pages on iOS** (same simulator, 2026-11-01, debug build): the Player page (Jason Smith, 19.5 runs, T20: header with round back, centred name and team, Save and Share; capsule stat switch; format segmented; 42% gauge with the four numbers; chart with the 19.5 line, values in the bars and every-other date / opponent labels; L5 75% / L10 44% / L20 42% / L30 29% / All 52% with the filter button; this match with the books table and the "Chart filters"), the Fixture page (Oman v Netherlands: centred title and series, the match container with the countdown, compact prop rows with price, L10 and ground, edge and bars) and a first-class match. Verified by eye against the reference screenshots, not pixel for pixel. Scoring and the unwrap now yield after 8 ms of work; in a debug build the lists still load in the background in a few seconds.
* **Not checked:** a release build, a physical iPhone, an iPhone with a home button or a small screen, light-mode system settings with the app forced dark (the simulator was in light mode and the app stayed dark), VoiceOver and Dynamic Type.
