# AGENTS.md: instructions for AI coding agents (Claude Code, Cursor, Copilot, Codex, Windsurf, JetBrains AI...)

Read [docs/PROJECT_GUIDE.md](docs/PROJECT_GUIDE.md) first (architecture, data flow, rules, gotchas), then [docs/OPERATIONS.md](docs/OPERATIONS.md) for secrets/runbooks.

## One-paragraph summary
Cricket dataset (Base + Source A-scraped provisional matches, `src/cricket_data`, `data/`), an hourly value-bets pipeline (`src/value_bets`), and a free StatsHub-style player-props website
(`site/`, builder in `src/cricket_site`). The site is a Vite + React + TypeScript app (shadcn/ui, Tailwind, Motion) over static JSON, with the stats engine (plain ESM, `site/packages/engine`) running in the browser and two serverless functions: `site/api/ask.js` (question → validated query plan) and `site/api/live.js` (Source A scores + player so-far for book-priced matches only, ~15 s cache; each match also carries `lines`, every priced line settled on the server).

## Commands
```bash
pip install -e ".[dev,value-bets]"      # python 3.10+
pytest -q                               # all python tests (tests/site = synthetic-match tests for the site builder)
ruff check src tests                    # lint (CI runs exactly this)
python scripts/check_public_safe.py     # secrets / personal paths / forbidden hostnames
cd site && npm ci && npm test           # node >= 20; engine/API/photo tests (node:test) + component tests (Vitest)
cd site && npm run build                # type-check + production build (CI runs this too)
python scripts/make_site_fixture.py     # regenerate site/tests/fixtures after changing builder output (pytest fails if stale)
python -m cricket_site.build --zip all_json.zip --data data --out site/public/data   # local data only if SITE_URL is unset
cd site && npm run dev                  # http://localhost:4173 — with SITE_URL in site/.env.local, /data and /api/live come from production
```

## Hard rules
1. Free only. No paid dependency may be *required*. Decimal odds only. Props/fancy markets only.
2. **All numbers on the site come from the engine/data, never from an LLM.** The LLM output goes through `sanitizePlan`; keep it whitelist-only.
3. Never mix formats (T20/ODI/Test/Hundred/T10/O60 separate). Keep the exchange void rules (docs/PROJECT_GUIDE.md section 1) intact; add tests with hand-computed numbers when touching them.
4. Never print/commit secrets. Do not write hosted-service hostnames (Vercel/Supabase subdomains) or home paths in tracked files (`check_public_safe.py` fails the build). Pass URLs via repo variables. The same goes for data sources: never name a provider or write its host in tracked files, docs, comments, commit messages or PR text (say "the source"; hosts come from environment variables, see docs/OPERATIONS.md); committed data stores host-relative links.
5. Generated files are not committed: `site/public/data/`, `site/public/sitemap.xml`, `site/public/robots.txt`, `.vercel/`, `.env*`. `site/tests/fixtures/` **is** committed (generated by `scripts/make_site_fixture.py`).
6. Work on a branch, add tests, open a PR; CI must pass (`build`, `site-js`, `test (3.10)`, `test (3.12)`). Python code must stay 3.10-compatible and stdlib-only in `src/cricket_site`. The site is React + TypeScript with a build step; free MIT libraries only, versions pinned by `package-lock.json`.
7. YAML workflows: lint with `actionlint`; never put `: ` unquoted inside a one-line `run:`.
8. Prefer editing existing modules over adding abstractions; match the surrounding style (compact, few comments, explain non-obvious rules in docstrings).
9. Props are never deleted: `value_bets/archive/` (one file per match, written by the pipeline) only grows; never add a job or script that removes or trims it, and keep the fixture page's fallback to it working.

## Where to look
* Rules for parsing matches -> `src/cricket_site/parse.py`; output format -> `build.py` (+ the table in PROJECT_GUIDE 5.1).
* Stats/markets/plan logic -> `site/packages/engine/*` (no DOM, tested with node:test); pages -> `site/src/pages/*`; shared pieces -> `site/src/components/app/*` and shadcn components in `site/src/components/ui/`; colours/tokens -> `site/src/index.css`.
* Design tokens -> `site/packages/tokens/tokens.json` (edit there, run `npm run tokens`; `src/tokens.generated.css` is committed). Storage abstraction and saved-list helpers -> `site/packages/storage`; app hook `site/src/lib/saved.ts`. Props screener filter state (URL-backed, pure) -> `site/src/lib/screener.ts`; filter view -> `components/app/screener-filters.tsx` (docs/SITE.md, "Mobile-first shell").
* Home rail order and its settings -> `site/src/lib/priority.ts`, `config/home_rail.json` (read at view time from the repo, no deploy; docs/SITE.md).
* LLM prompt/provider -> `site/packages/engine/prompt.js`, `site/api/ask.js`.
* Live scores -> `site/packages/engine/live.js`, `site/api/live.js` (books-priced matches only). A Test at close of play stays `live` for 6 days, with scores and the session badge (Stumps / Lunch / Rain delay / Paused); the source's home list still has it after `/schedule` drops it; status 2 without a result is a day break, not the end.
* Where a priced line stands (so far / final / Cleared / Missed / Push / Not in XI) -> settled on the server: `settleLines` in `live.js` (matching and verdicts, one place), shown by `lineStanding` / `lineNotIn`; a finished match's results are stored in its archive file by `settle` in `src/value_bets/archive.py` (PROJECT_GUIDE 5.4c). Fix a matching or settlement bug there, not in a component. Fancy so-far is the same 15 s snapshot via `fancyStanding` (innings totals, not player ids), overlaid at view time on Match Fancy / Fancy cards; do not bake it into the scored history. Player-performance so-far is runs + 20×wickets + 10×catches + 25×stumpings from the scorecard how-out (2 catch, 3 caught-and-bowled, 8 stumping). Live tracking is the 15 s `/api/live` poll (no websocket): `Tick` flashes a so-far or a price that moved; `engine/tape.js` buckets high-odds hits (≥2.50 cleared) and low-odds misses (≤1.40 missed).
* Who is who across the data, the live source and the books -> the player-identity table: `src/cricket_site/identity.py` (builder), `data/mappings/player_identity.csv` (links checked by hand), `site/packages/engine/identity.js` (lookups). Ids first, names only as the fallback; fix a bad link with a line in the CSV, not with another name rule (PROJECT_GUIDE 5.7).
* Images/ids -> `src/cricket_site/crex_assets.py`, `assets_sync.py`, `site/src/lib/photos.js`, `site/src/lib/assets.ts`, `supabase/migrations/`.
* Deploy/schedules -> `.github/workflows/site.yml`.
