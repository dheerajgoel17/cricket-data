# Props.Cash audit and redesign recommendation

Date: 2026-10-31. Audit only: no application code was changed. Companion files: `SCREEN_INVENTORY.md`, `ARCHITECTURE.md`, `DESIGN_SYSTEM.md`, `OPEN_QUESTIONS.md`, `screenshots/`.

## 0. Method and limits (read first)
- Props.Cash was inspected in the user's own signed-in Chrome through the Chrome extension. No credentials, cookies or tokens were read or stored; no purchases, saves or setting changes were made. The profile photo is masked in screenshots.
- Desktop viewport was ~1430 px. The window could not be resized, so mobile screens come from loading the same signed-in app in a 390 px frame (real CSS breakpoints, not a real device). A logged-out mobile view was also loaded in the built-in browser; nothing was entered there.
- The account is on a free trial of 5 player opens per day. One player was opened (3 → 2 left). Second pass covered the matchup drawer, chart filters, team pages, search groups and game-chip filtering. Not reached: Pro-only screens, saving filters/stars, a real device. See SCREEN_INVENTORY "Not inspected".

## 2. Props.Cash findings

### Product patterns worth adapting (all observed)
1. **Screener first.** The landing page is the table of prop lines, not a marketing page: prop-type chip rail, game rail by date, sortable "L10 chart" column, hit rates for season/H2H/DvP, matchup grade, edge meter.
2. **One URL per prop-line, not per player.** Detail URL is `/nfl/<uuid>`; the prop-type tab rail stays on top so switching markets keeps the player.
3. **Two controls drive everything on detail:** line (stepper → alt-lines drawer with prices by book) and window (2026/2025/H2H/L5/L10/L20/L30). Both re-render the chart and hit rate instantly.
4. **Filters as accordions with the value shown in the header**, applied as a drawer (desktop) or full page (mobile), with Save Filter Combo.
5. **Context chips on the chart** (DvP, Dog, Away, Day Game, 1Q, snap %) filter the sample: this is the single richest analysis feature. Over-filtering yields a plain "No chart data available" with hit rates `–`; a cricket version should show the remaining sample size and a suggested relaxation.
5c. **Team pages are reached by search and share the screener's row format**: results strip, top performers, team props, team-defense table, share-of-offence donut, injury/health cards. URLs are readable (`/nfl/team/IND`) while player URLs are opaque UUIDs.
5b. **Matchup is a drawer, not a page**: a team-colour banner, past results, per-stat league ranks as bars, and a table of recent games against that defence.
6. **Matchup explained in plain text + grade dial**, injury/roster activity, teammate "when he hits" correlations.
7. **Mobile is re-composed, not shrunk:** fewer columns, sparkline instead of chart, floating nav, FAB for filters, full-screen filter page, trial banner always visible.
8. **Watchlist at prop-line level** with an empty state telling the user how to fill it.
9. **Search** groups results and offers a direct "Lines" action.

## 7. Executive summary
1. **Architecture:** keep React/Vite/Tailwind on the web, extract `engine`, data client, formatters and tokens into workspace packages, and add Expo apps later with native UI built on those packages.
2. **Why:** the engine is already DOM-free and tested; the UI layer (Radix/shadcn, Tailwind, Ionic web components, Motion, hand-made DOM chart) would be replaced under Tamagui anyway, and Props.Cash's own mobile UI is a re-composition, not a scaled desktop, which favours platform-specific shells.
3. **Biggest risk:** the redesign scope. Props.Cash's strength is the line + window + context-filter workflow, which needs cricket-specific stats (venue, innings, bowler type, toss) that may not exist in the engine yet. Second: two UI codebases drifting apart.
4. **First three steps:** (a) resolve the `AGENTS.md` merge conflict and decide the open questions; (b) make `site/src/index.css` tokens the single generated source and move `engine` + pure `lib` helpers to packages with tests green; (c) rebuild the mobile props screener row + full-screen filter flow + line/window controls on the existing `ChartBars`.
5. **Decided:** iOS and Android together; no login, everything free, saved state on the device. **Still open:** is SEO for player pages a priority; may `research/` be committed; odds/row style on mobile; store-policy review for betting-adjacent content.
